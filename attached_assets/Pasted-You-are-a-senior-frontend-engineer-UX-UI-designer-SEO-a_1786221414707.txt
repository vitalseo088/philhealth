7. DATA ARCHITECTURE — VERY IMPORTANT
==================================================

THIS IS THE MOST IMPORTANT CHANGE FROM THE PREVIOUS VERSION.

Do not make the tools depend on an empty "verified data" state.

Create a local data layer.

Every tool must have usable seed data.

The data layer must be independent from the UI.

Example:

const contributionRules = [
    {
        year: 2026,
        memberType: "employed",
        ...
    }
];

Every factual dataset must contain:

- id
- title/name
- category
- description
- source
- sourceUrl
- effectiveDate
- lastVerified
- status

Possible status:

"verified"
"illustrative"
"needs-review"

CRITICAL:

If current official information cannot be verified, do NOT fabricate it.

Instead:

- use clearly marked illustrative data for demonstration where calculation logic is useful;
- explain the limitation;
- provide the official source link;
- keep the calculation engine fully functional;
- allow the dataset to be replaced easily later.

NEVER allow the entire tool to become blank merely because one dataset is unavailable.

For example:

BAD:

"No verified data has been supplied."

GOOD:

"Enter your information below to calculate an illustrative estimate. The result is based on the rules currently loaded into this tool. Always verify the applicable amount with official PhilHealth information."

Then show the result.

Every tool must still perform a meaningful operation.
